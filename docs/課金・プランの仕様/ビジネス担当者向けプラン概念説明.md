# プラン機能の概念説明（ビジネス担当者向け）

## このドキュメントの目的

このシステムで提供するプランをどのように設計するかを検討する方に向けて、プランの概念と制限可能な要素について説明します。

---

## プランとは

**プラン**とは、「ユーザがどの機能を、どれだけ使えるか」を定義したサービスの契約単位です。

例えば：

- **Freeプラン**: 基本機能のみ、LLMは1日10回まで
- **Standardプラン**: 主要機能すべて、LLMは無制限（一部モデルは月400回まで）
- **Proプラン**: すべての機能、すべてのLLMが無制限

ユーザは常に1つのプランに加入しており、複数のプランに同時加入することはできません。

---

## プランで制限できる3つの要素

プランでは、以下の3つの要素について「使える/使えない」「無制限/回数制限」を設定できます。

### 1. 機能（Feature）

チャット、RAG、画像生成、翻訳など、システムが提供する各種機能へのアクセスを制御できます。

**設定可能な内容**：

- この機能は使える / 使えない

**例**：

```
Freeプラン:
  - チャット機能: 利用可能
  - 議事録生成: 利用不可
  - 翻訳機能: 利用不可

Standardプラン:
  - チャット機能: 利用可能
  - 議事録生成: 利用可能
  - 翻訳機能: 利用可能
```

### 2. LLMモデル（AI）

Claude 3.5 Sonnet、Claude 3 Opusなど、各種LLMモデルへのアクセスを制御できます。

**設定可能な内容**：

- 利用不可
- 無制限に利用可能
- 日次制限（1日あたり〇回まで）
- 月次制限（1ヶ月あたり〇回まで）

**例**：

```
Freeプラン:
  - Claude 3.5 Haiku: 1日10回まで
  - Claude 3.5 Sonnet: 利用不可
  - Claude 3 Opus: 利用不可

Standardプラン:
  - Claude 3.5 Haiku: 無制限
  - Claude 3.5 Sonnet: 無制限
  - Claude 3 Opus: 月400回まで

Proプラン:
  - すべてのモデル: 無制限
```

**回数制限の詳細**：

- **1日10回まで**と設定した場合、毎日0時（UTC）にカウントがリセットされ、再び10回使えるようになります
- **月400回まで**と設定した場合、毎月1日にカウントがリセットされます
- カウントは各ユーザごとに独立して管理されます

### 3. アシスタント（Assistant）

特定の用途に特化したアシスタント（カスタマイズされたAI）へのアクセスを制御できます。

**設定可能な内容**：

- 各アシスタントを使える / 使えない

**想定例**：

```
Freeプラン:
  - アシスタントA: 利用可能
  - アシスタントB: 利用不可

Proプラン:
  - すべてのアシスタント: 利用可能
```

## プランの適用パターン

プランは、以下の4つのパターンでユーザに適用されます。

### 1. デフォルトプラン（必須）

新規登録したすべてのユーザに自動的に適用される無料のプランです。

**特徴**：

- システムに必ず1つ存在する必要があります
- 通常は「Freeプラン」として設定されます
- 有料プランに加入していないすべてのユーザが、このプランを利用します

### 2. サブスクリプション契約

ユーザがStripe、Apple、Googleなどの課金プラットフォーム経由で購入したプランです。

**特徴**：

- 定期的に課金が発生します
- 支払いが継続する限り、プランが有効です
- ユーザ自身が解約するまで自動更新されます

### 3. トライアル・キャンペーン (将来的に実装予定)

期間限定で提供されるプランです。

**特徴**：

- 「14日間無料トライアル」「新規登録キャンペーン」などで使用します
- 期限が来ると自動的にデフォルトプランに戻ります
- ユーザが過去にトライアルを使用したかどうかを記録できます

### 4. 管理者による手動付与

管理者が特定のユーザに対して例外的に適用するプランです。

**特徴**：

- カスタマーサポート対応などで使用します
- 期限を設定することも、無期限にすることもできます
- すべての操作が監査ログに記録されます

## 具体的なプラン設計例

実際にどのようなプランが設計できるかの例を示します。

### 例1：シンプルな3段階プラン

```
Freeプラン（$0/月）
  LLM:
    - Claude 3.5 Haiku: 1日10回
  機能:
    - チャット機能: 利用可能
    - その他の機能: 利用不可

Standardプラン（$20/月）
  LLM:
    - Claude 3.5 Haiku: 無制限
    - Claude 3.5 Sonnet: 無制限
    - Claude 3 Opus: 月400回
  機能:
    - チャット機能: 利用可能
    - RAG機能: 利用可能
    - 画像生成: 利用可能
    - 翻訳機能: 利用可能

Proプラン（$100/月）
  LLM:
    - すべてのモデル: 無制限
  機能:
    - すべての機能: 無制限
```

### 例2：用途別プラン

```
個人利用プラン（$10/月）
  - 軽量モデル（Haiku）: 無制限
  - 標準モデル（Sonnet）: 月100回
  - 基本機能のみ

ビジネスプラン（$50/月）
  - 標準モデル（Sonnet）: 無制限
  - 高度なモデル（Opus）: 月500回
  - すべての機能が利用可能

エンタープライズプラン（$200/月）
  - すべてのモデル: 無制限
  - すべての機能: 無制限
  - 専用サポート付き
```

### 例3：トライアルプラン

```
Standard 14日間トライアル（$0、期限付き）
  - Standardプランと同じ内容を14日間利用可能
  - 14日後、自動的にFreeプランに戻る
  - ユーザは過去に1回のみトライアルを利用可能
```

## よくある質問（FAQ）

### Q1. プランの価格はどこで設定するのか？

**A.** プランの価格は、このシステムではなく、課金プラットフォーム側（Stripe、Apple、Google）で設定します。

このシステムでは：

- プランに含まれる機能と制限を定義します
- 課金プラットフォーム側の商品IDと紐付けます

価格設定は、各課金プラットフォームの管理画面で行います。

### Q2. 回数制限のカウントはいつリセットされるか？

**A.** リセットタイミングは制限の種類によって異なります：

- **日次制限**: 毎日0時にリセット
- **月次制限**: 毎月1日の0時にリセット

### Q3. ユーザが日次制限に達したらどうなるか？

**A.** その日はその機能/モデルを使用できなくなります。翌日0時にカウントがリセットされると、再び使用できるようになります。

ユーザには「本日の利用上限に達しました。明日0時にリセットされます」といったメッセージを表示することが推奨されます。

### Q4. プランをアップグレード/ダウングレードした場合、回数カウントはどうなるか？

**A.** プラン変更時には、回数カウントはリセットされます。

例：

- FreeプランでHaikuを10回使用済み（上限10回）
- Standardプランにアップグレード
- Standardプランでは無制限になるため、カウントは無関係になります

### Q5. 複数の課金プラットフォームで異なる価格を設定できるか？

**A.** はい、可能です。

各課金プラットフォーム用に別々のプランを作成します：

```
standard_stripe（Stripe用）- $20/月
standard_apple（Apple用）- $24.99/月（Appleの手数料を考慮）
standard_google（Google用）- $24.99/月（Googleの手数料を考慮）
```

すべて同じ内容（機能、制限）を持ちますが、価格と課金プラットフォームが異なります。

### Q6. デフォルトプランは必須か？

**A.** はい、必須です。

新規登録したユーザは、自動的にデフォルトプランに加入します。デフォルトプランが存在しない場合、新規ユーザは何も利用できない状態になってしまいます。

通常は、無料で基本的な機能のみを提供する「Freeプラン」をデフォルトプランとして設定します。

### Q7. ユーザは自分のプランを確認できるか？

**A.** はい、できます。

ユーザ向けの画面で、現在加入しているプランの内容を表示できます：

- プラン名
- 利用可能な機能
- 各モデルの利用上限
- 今日/今月の残り利用回数

### Q8. 管理者は既存ユーザのプランを確認/変更できるか？

**A.** はい、できます。

管理者向け画面では、以下の操作が可能です：

- 全ユーザのプラン加入状況を確認
- 特定ユーザのプランを手動で変更
- 各プランの契約者数を確認
- プランの作成・ステータス変更

### Q9. トライアルを一度使ったユーザは、再度トライアルを利用できるか？

**A.** 運用ポリシー次第です。

システムとしては、ユーザがトライアルを使用した履歴を記録できます。

- 「1人につき1回のみトライアル可能」というポリシーなら、過去の利用履歴をチェックして拒否できます
- 「キャンペーンごとに利用可能」というポリシーなら、キャンペーンIDごとに履歴を管理できます

### Q10. プランの数が増えすぎた場合、古いプランを削除できるか？

**A.** 契約者がいる場合は削除できません。

プランのステータス遷移：

1. **active**（新規加入可能） → **closed_to_new**（新規加入不可、既存契約者は継続）
2. **closed_to_new** → **deprecated**（廃止、契約者が0人になってから）

契約者が0人になるまでは、プランをシステムから完全に削除することはできません。
古いプランの契約者への対応（Freeプランなどへの移行対応など）が行われ、契約者が0人になると削除することができます。

---

## まとめ

プラン機能を使うことで、柔軟なサービス提供が可能になります：

- **3つの要素を制御**：機能、LLMモデル、アシスタント（将来対応）
- **回数制限の柔軟性**：無制限、日次制限、月次制限を組み合わせられます
- **プラン数に上限なし**：必要なだけプランを作成できます
- **4つの適用パターン**：デフォルト、サブスクリプション、トライアル、手動付与
- **グランドファザリング対応**：既存契約者に影響を与えずに新プランを導入できます

プラン設計時には、ユーザのニーズと収益モデルを考慮しながら、上記の制約とルールを踏まえて検討してください。
