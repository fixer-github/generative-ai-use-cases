# 統括責務が必要とするイベント形式定義

**作成日**: 2025-11-13
**対象**: 購入・変更・解約などの複数ステップの処理を統括する責務
**前提資料**: 統括責務実装前の必須修正事項.md（修正5-1）

---

## 1. エグゼクティブサマリー

本資料では、統括責務（購入・変更・解約などの複数ステップ処理のオーケストレーター）が決済連携（Payment Gateway）から受信する**EventBridgeイベントの標準形式**を定義します。

### 定義の目的

1. **ビジネスイベント駆動**: プラットフォーム固有のイベントタイプではなく、ビジネスの意味に基づいたイベントタイプを使用
2. **情報の正規化**: 統括責務が必要とする情報（subscriptionId、userId等）をトップレベルに配置し、プラットフォーム固有の構造に依存しない
3. **EventBridgeルールでのフィルタリング**: イベントタイプごとに適切なハンドラーを起動できる

### 前提条件

- Payment Gateway Webhook層で、プラットフォーム固有イベントからビジネスイベントへの変換を実施
- 統括責務のWebhookイベントハンドラーは、この形式のイベントのみを処理する

## 2. イベント形式の完全定義

### 2.1 TypeScript型定義

```typescript
/**
 * 統括責務が受信するEventBridgeイベントの標準形式
 */
interface OrchestratorWebhookEvent {
  /** EventBridgeのバージョン（固定値） */
  version: '0';

  /** イベントの一意識別子（EventBridge自動生成） */
  id: string;

  /** イベント発生元（固定値） */
  source: 'billing.payment-gateway';

  /** ビジネスイベントタイプ */
  'detail-type': BusinessEventType;

  /** AWSアカウントID */
  account: string;

  /** イベント発生日時（ISO 8601形式） */
  time: string;

  /** AWSリージョン */
  region: string;

  /** 関連リソースのARN配列 */
  resources: string[];

  /** イベント詳細情報 */
  detail: EventDetail;
}

/**
 * ビジネスイベントタイプ（統括責務が処理する4つのイベント）
 */
type BusinessEventType =
  | 'payment.succeeded' // 支払い更新成功
  | 'payment.failed' // 支払い失敗
  | 'subscription.canceled' // サブスクリプションキャンセル
  | 'payment.refunded'; // 返金

/**
 * イベント詳細情報
 */
interface EventDetail {
  /** プラットフォーム種別 */
  platform: 'stripe' | 'apple' | 'google';

  /** テナントID */
  tenantId: string;

  /** プラットフォーム固有のイベントID */
  eventId: string;

  /** プラットフォーム固有の元のイベントタイプ（参照用） */
  originalEventType: string;

  /** サブスクリプションID（必須） */
  subscriptionId: string;

  /** ユーザーID（必須） */
  userId: string;

  /** プランID（取得可能な場合） */
  planId?: string;

  /** サブスクリプション有効期限（取得可能な場合、ISO 8601形式） */
  expirationDate?: string;

  /** 支払い金額（payment.succeeded、payment.refunded時に含まれる） */
  amount?: number;

  /** 通貨コード（payment.succeeded、payment.refunded時に含まれる、ISO 4217形式） */
  currency?: string;

  /** プラットフォーム固有の決済ID（参照用） */
  platformPaymentId?: string;

  /** エラーメッセージ（payment.failed時に含まれる） */
  errorMessage?: string;

  /** プラットフォーム固有の生イベントデータ（詳細調査用） */
  eventData: Record<string, any>;
}
```

### 2.2 フィールド詳細説明

#### 必須フィールド（detail内）

| フィールド          | 型     | 説明                             | 取得元                                                                          |
| ------------------- | ------ | -------------------------------- | ------------------------------------------------------------------------------- |
| `platform`          | string | 課金プラットフォーム             | Webhook受信時に識別                                                             |
| `tenantId`          | string | テナントID                       | リクエストパスから取得                                                          |
| `eventId`           | string | プラットフォーム固有のイベントID | Stripe: `event.id`<br>Apple: `notificationUUID`<br>Google: `messageId`          |
| `originalEventType` | string | 元のイベントタイプ               | Stripe: `event.type`<br>Apple: `notificationType`<br>Google: `notificationType` |
| `subscriptionId`    | string | サブスクリプションID             | **抽出ロジック参照**（後述）                                                    |
| `userId`            | string | ユーザーID                       | **抽出ロジック参照**（後述）                                                    |

#### オプションフィールド（detail内）

| フィールド          | 型     | 説明                           | 含まれるイベント                        |
| ------------------- | ------ | ------------------------------ | --------------------------------------- |
| `planId`            | string | プランID                       | 取得可能な場合のみ                      |
| `expirationDate`    | string | 有効期限（ISO 8601）           | `payment.succeeded`時                   |
| `amount`            | number | 支払い金額                     | `payment.succeeded`、`payment.refunded` |
| `currency`          | string | 通貨コード（ISO 4217）         | `payment.succeeded`、`payment.refunded` |
| `platformPaymentId` | string | プラットフォーム固有の決済ID   | `payment.succeeded`、`payment.refunded` |
| `errorMessage`      | string | エラーメッセージ               | `payment.failed`                        |
| `eventData`         | object | プラットフォーム固有の生データ | 全イベント（詳細調査用）                |

## 3. ビジネスイベントタイプの定義

### 3.1 payment.succeeded（支払い更新成功）

#### 意味

サブスクリプションの定期支払いが成功し、有効期限が延長された

#### 統括責務での処理

1. サブスクリプション有効期限を延長（Subscription Management Service呼び出し）
2. プラン適用状態を確認し、`scheduled_termination`でなければ有効期限を延長（Plan Management Service呼び出し）
3. 支払い履歴を記録（Subscription Management Service呼び出し）

#### 必須フィールド

- `subscriptionId`
- `userId`
- `expirationDate`
- `amount`
- `currency`

#### サンプルイベント

```json
{
  "version": "0",
  "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "source": "billing.payment-gateway",
  "detail-type": "payment.succeeded",
  "account": "123456789012",
  "time": "2025-11-13T10:30:00Z",
  "region": "ap-northeast-1",
  "resources": [],
  "detail": {
    "platform": "stripe",
    "tenantId": "tenant-abc123",
    "eventId": "evt_1ABC2DEF3GHI",
    "originalEventType": "invoice.payment_succeeded",
    "subscriptionId": "sub_1XYZ2ABC3DEF",
    "userId": "user-123456",
    "planId": "plan_standard_monthly",
    "expirationDate": "2025-12-13T10:30:00Z",
    "amount": 1980,
    "currency": "jpy",
    "platformPaymentId": "pi_1ABC2DEF3GHI",
    "eventData": {
      /* Stripe生イベントデータ */
    }
  }
}
```

### 3.2 payment.failed（支払い失敗）

#### 意味

サブスクリプションの定期支払いに失敗した（猶予期間に入る）

#### 統括責務での処理

1. サブスクリプション状態を`past_due`（猶予期間）に変更（Subscription Management Service呼び出し）
2. 支払い失敗履歴を記録（Subscription Management Service呼び出し）
3. ユーザーに支払い方法更新を通知（通知サービス呼び出し、今後実装予定）

#### 必須フィールド

- `subscriptionId`
- `userId`
- `errorMessage`

#### サンプルイベント

```json
  "source": "billing.payment-gateway",

  "time": "2025-11-13T10:30:00Z",
```

### 3.3 subscription.canceled（サブスクリプションキャンセル）

#### 意味

サブスクリプションがキャンセルされた（支払い失敗後のリトライ期限切れ、またはユーザー/管理者による明示的なキャンセル）

#### 統括責務での処理

1. サブスクリプション状態を`canceled`に変更（Subscription Management Service呼び出し）
2. プラン適用を終了（Plan Management Service呼び出し）
3. 権限を剥奪（Authorization Service呼び出し）
4. デフォルトプランに遷移（Plan Management Service呼び出し）
5. ユーザーにキャンセル完了を通知（通知サービス呼び出し、今後実装予定）

#### 必須フィールド

- `subscriptionId`
- `userId`

#### サンプルイベント

```json
{
  "version": "0",
  "id": "c3d4e5f6-g7h8-9012-cdef-123456789012",
  "source": "billing.payment-gateway",

  "account": "123456789012",
  "time": "2025-11-13T10:30:00Z",
  "region": "ap-northeast-1",

    "platform": "stripe",
    "tenantId": "tenant-abc123",
```

## 4. プラットフォーム別マッピング

### 4.1 Stripe イベントマッピング

| Stripeイベントタイプ            | ビジネスイベント        | 備考                   |
| ------------------------------- | ----------------------- | ---------------------- |
| `invoice.payment_succeeded`     | `payment.succeeded`     | 定期支払い成功         |
| `invoice.payment_failed`        | `payment.failed`        | 定期支払い失敗         |
| `customer.subscription.deleted` | `subscription.canceled` | サブスクリプション削除 |
| `charge.refunded`               | `payment.refunded`      | 返金処理               |

#### マッピング対象外のStripeイベント

以下のイベントはビジネスイベントにマッピングせず、EventBridge送信もスキップ（または別形式で送信）：

- `customer.subscription.updated`: サブスクリプション属性の変更（プラン変更など）。これらは統括責務のAPI経由で処理されるため、Webhookイベントとして処理する必要なし
- `customer.subscription.created`: 新規作成は購入フローで処理
- `invoice.created`: 請求書作成は直接的な処理不要

### 4.2 Apple イベントマッピング

| Appleイベントタイプ         | ビジネスイベント        | 備考                                               |
| --------------------------- | ----------------------- | -------------------------------------------------- |
| `DID_RENEW`                 | `payment.succeeded`     | サブスクリプション更新成功                         |
| `DID_FAIL_TO_RENEW`         | `payment.failed`        | 更新失敗（猶予期間）                               |
| `DID_CHANGE_RENEWAL_STATUS` | `subscription.canceled` | 自動更新OFF時のみ<br>（`autoRenewStatus` = false） |
| `REFUND`                    | `payment.refunded`      | App Store返金                                      |

#### マッピング条件

- `DID_CHANGE_RENEWAL_STATUS`は`autoRenewStatus`が`false`の場合のみ`subscription.canceled`にマッピング
- `autoRenewStatus`が`true`の場合はマッピング対象外（再開処理として別途実装の可能性あり）

#### マッピング対象外のAppleイベント

- `INITIAL_BUY`: 新規購入は購入フローで処理
- `DID_CHANGE_RENEWAL_PREF`: プラン変更は統括責務のAPI経由で処理
- `GRACE_PERIOD_EXPIRED`: 猶予期間終了後に`DID_FAIL_TO_RENEW`または`subscription.canceled`イベントが来るため不要

### 4.3 Google イベントマッピング

| Googleイベントタイプ           | ビジネスイベント        | 備考                       |
| ------------------------------ | ----------------------- | -------------------------- |
| `SUBSCRIPTION_RENEWED`         | `payment.succeeded`     | サブスクリプション更新成功 |
| `SUBSCRIPTION_IN_GRACE_PERIOD` | `payment.failed`        | 支払い失敗（猶予期間）     |
| `SUBSCRIPTION_CANCELED`        | `subscription.canceled` | キャンセル（ユーザー操作） |
| `SUBSCRIPTION_REVOKED`         | `payment.refunded`      | Google Play返金            |

#### マッピング対象外のGoogleイベント

- `SUBSCRIPTION_PURCHASED`: 新規購入は購入フローで処理
- `SUBSCRIPTION_PAUSED`: 一時停止機能は今後実装予定
- `SUBSCRIPTION_RESUMED`: 再開機能は今後実装予定
- `SUBSCRIPTION_ON_HOLD`: Account Hold状態（猶予期間後の状態、統括責務では`payment.failed`で処理）

## 5. 情報抽出ロジック（プラットフォーム別）

### 5.1 Stripe

#### subscriptionId

```typescript
// invoice.payment_succeeded, invoice.payment_failed
const subscriptionId = event.data.object.subscription; // Stripe Subscription ID

// customer.subscription.deleted
const subscriptionId = event.data.object.id; // Stripe Subscription ID

// charge.refunded
// Chargeからinvoiceを取得し、そこからsubscriptionを取得
const invoiceId = event.data.object.invoice;
// invoiceIdからinvoiceを取得してsubscriptionIdを抽出（API呼び出しまたはメタデータ利用）
```

#### userId

```typescript
// Stripeのcustomerメタデータから取得（購入時に設定）
const customer = event.data.object.customer; // Customer ID
// customerオブジェクトのmetadata.userIdを取得（API呼び出しまたはイベントデータ内に含まれる場合）
const userId = customer.metadata.userId;

// または、subscription/invoice内のmetadataから取得
const userId = event.data.object.metadata?.userId;
```

#### planId

```typescript
// invoice内のline itemsからpriceIdを取得し、それをplanIdにマッピング
const priceId = event.data.object.lines.data[0].price.id;
// priceId → planIdのマッピングはPlan Management Serviceで管理
```

#### expirationDate

```typescript
// invoice.payment_succeeded時
const expirationTimestamp = event.data.object.lines.data[0].period.end; // Unixタイムスタンプ
const expirationDate = new Date(expirationTimestamp * 1000).toISOString();
```

#### amount / currency

```typescript
const amount = event.data.object.amount_paid; // または total
const currency = event.data.object.currency; // 例: "jpy"
```

### 5.2 Apple

#### subscriptionId

```typescript
// JWS decodedPayloadから取得
const subscriptionId =
  decodedPayload.data.transactionInfo.originalTransactionId;
```

#### userId

```typescript
// JWS decodedPayloadのappAccountTokenから取得（購入時に設定）
const userId = decodedPayload.data.appAccountToken;
// または、originalTransactionIdからRDB/DynamoDBで逆引き
```

#### planId

```typescript
// productIdからplanIdにマッピング

// productId → planIdのマッピングはPlan Management Serviceで管理
```

#### expirationDate

```typescript
const expirationTimestamp = decodedPayload.data.transactionInfo.expiresDate; // ミリ秒単位
const expirationDate = new Date(expirationTimestamp).toISOString();
```

#### amount / currency

```typescript
// Appleはイベント内に直接金額が含まれないため、productIdから取得
// または、transactionInfoから取得可能な場合あり

// amountはproductIdから製品情報を取得して参照
```

## 6. 実装ガイドライン

### 6.1 実装場所

Payment Gateway Webhook受信Lambda関数内でイベント変換を実施：

- **Stripe**: `/packages/cdk/lambda/billing/payment-gateway/webhook/stripe/receiveWebhook.ts`
- **Apple**: `/packages/cdk/lambda/billing/payment-gateway/webhook/apple/receiveNotification.ts`
- **Google**: `/packages/cdk/lambda/billing/payment-gateway/webhook/google/receiveNotification.ts`

### 6.2 実装手順

#### ステップ1: イベントマッピング関数の実装

各プラットフォーム用に、以下の関数を実装：

```typescript
/**
 * プラットフォーム固有イベントをビジネスイベントにマッピング
 * @returns ビジネスイベントタイプ、またはnull（マッピング対象外）
 */
function mapToBusinessEvent(
  platform: 'stripe' | 'apple' | 'google',
  originalEventType: string,
  eventData: any
): BusinessEventType | null;
```

#### ステップ2: 情報抽出関数の実装

各プラットフォーム用に、以下の関数を実装：

```typescript
/**
 * イベントデータから必須フィールドを抽出
 */
async function extractEventDetail(
  platform: 'stripe' | 'apple' | 'google',
  eventData: any,
  tenantId: string
): Promise<Partial<EventDetail>>;
```

#### ステップ3: EventBridge送信処理の更新

既存のEventBridge送信コードを以下のように変更：

**変更前（現在）:**

```typescript
{
  Source: 'payment-gateway.webhook',
  DetailType: 'StripeWebhookReceived',
  Detail: JSON.stringify({
    platform: 'stripe',
    eventId,
    eventType,
    eventData: stripeEvent,
    tenantId,
  }),
}
```

**変更後:**

```typescript
// ビジネスイベントにマッピング
const businessEventType = mapToBusinessEvent('stripe', eventType, stripeEvent);

if (!businessEventType) {
  // マッピング対象外のイベントはスキップ（またはログのみ記録）
  console.log(`Event type ${eventType} is not mapped to business event. Skipping.`);
  return { statusCode: 200, body: JSON.stringify({ received: true, skipped: true }) };
}

// 情報抽出
const eventDetail = await extractEventDetail('stripe', stripeEvent, tenantId);

// EventBridge送信
{
  Source: 'billing.payment-gateway',
  DetailType: businessEventType,
  Detail: JSON.stringify({
    ...eventDetail,
    platform: 'stripe',
    tenantId,
    eventId,
    originalEventType: eventType,
    eventData: stripeEvent, // 生データも含める（詳細調査用）
  }),
}
```
