# ユーザが各機能を使える権限と一日何回使えるかを判定する - 技術実装構成

## 概要

本資料は、「ユーザが各機能を使える権限と一日何回使えるかを判定する」責務の技術的な実装構成を定義します。既存の[実装イメージ.md](./実装イメージ.md)を基に、現在のシステム実装パターンに沿った具体的な技術構成を示します。

## 前提条件

### システム構成の前提

- **Database Per Tenantsパターン**: テナントごとにデータベースを分離
- **Lambda関数**: 共通リソース（状態なし）として全テナントで共有
- **DynamoDB**: テナント専用リソース（状態あり）としてテナントごとに作成
- **OpenFGA**: 既存実装あり（ECS Fargate + PostgreSQL RDS + API Gateway構成）
- **マルチテナント認証**: Cognito Identity Pool + IAM Role + Assume Roleによるテナント間分離

### 責務の制約

- **「プラン」概念を持たない**: この責務内では「権限付与ID」という抽象的な識別子のみを扱う
- **疎結合の維持**: プラン管理責務との疎結合を維持し、ToB向けなど別の文脈でも再利用可能
- **期限管理の外部化**: 有効期限の概念は外部（プラン管理責務）で管理

### 1.2 Lambda関数の詳細仕様

#### 1.2.1 権限付与Lambda関数 (`grantPermission.ts`)

**役割**: OpenFGAとDynamoDBに権限情報を登録する

**呼び出し元**: プラン管理などの他の責務（Lambda関数呼び出し）

**入力パラメータ**:
```typescript
interface GrantPermissionRequest {
  tenantId: string;           // テナントID
  userId: string;             // ユーザID
  grantId: string;            // 権限付与ID（呼び出し元が生成するUUID）
  features: Array<{
    featureId: string;        // 機能ID（例: "feature-model-a"）
    limitType: 'unlimited' | 'daily' | 'monthly';
    limitCount?: number;      // limitTypeが'unlimited'以外の場合に必須
  }>;
  sourceType: string;         // 付与元のタイプ（例: "subscription", "trial", "campaign", "manual"）
  sourceId: string;           // 付与元のID（サブスクリプションID、キャンペーンIDなど）
}
```

**処理内容**:
1. リクエストのバリデーション（必須パラメータ、テナントID検証）
2. OpenFGAへのアクセス権限登録
   - OpenFGA API Gatewayエンドポイントへのリクエスト
   - 各機能に対して `WriteTuples` APIを実行
   - 関係性: `user:{userId}` → `can_access` → `feature:{featureId}`
3. 回数制限がある機能についてDynamoDBにカウンター情報を作成
   - テナント専用の利用回数カウントテーブルに書き込み
   - 次回リセット日時の計算（日次は翌日0時UTC、月次は翌月1日0時UTC）
4. 権限付与履歴をDynamoDBに記録
   - テナント専用の権限付与履歴テーブルに書き込み
5. エラーハンドリング
   - OpenFGA書き込み失敗時はロールバック（DynamoDBへの書き込みを実行しない）
   - DynamoDB書き込み失敗時はOpenFGAの関係性を削除してロールバック

**出力**:
```typescript
interface GrantPermissionResponse {
  success: true;
  grantId: string;
  grantedAt: string; // ISO8601形式
}
```

**環境変数**:
- `OPENFGA_API_ENDPOINT`: OpenFGA API Gatewayエンドポイント
- `OPENFGA_STORE_ID`: OpenFGA Store ID

**IAMポリシー要件**:
- テナント専用DynamoDBテーブルへの書き込み権限（PutItem、UpdateItem）
- OpenFGA API Gatewayへの実行権限（execute-api:Invoke）
- テナントロールのAssumeRole権限（クロスアカウントアクセス）

**タイムアウト**: 30秒

**メモリ**: 512 MB

---

#### 1.2.2 権限剥奪Lambda関数 (`revokePermission.ts`)

**役割**: OpenFGAとDynamoDBから権限情報を削除する

**呼び出し元**: プラン管理などの他の責務（Lambda関数呼び出し）

**入力パラメータ**:
```typescript
interface RevokePermissionRequest {
  tenantId: string;  // テナントID
  grantId: string;   // 権限付与ID
}
```

**処理内容**:
1. リクエストのバリデーション
2. DynamoDBの権限付与履歴テーブルから該当する権限情報を取得
   - grantIdをキーにQueryを実行
   - 権限付与時に登録された機能リストを取得
3. OpenFGAから該当する関係性を削除
   - 各機能に対して `DeleteTuples` APIを実行
4. DynamoDBの利用回数カウントテーブルから該当するカウンター情報を削除
   - grantId-indexを使用してQueryを実行
   - 該当する全てのアイテムをBatchWriteItemで削除
5. 権限付与履歴テーブルの状態を更新
   - statusを`active`から`revoked`に変更
   - revokedAtタイムスタンプを記録

**出力**:
```typescript
interface RevokePermissionResponse {
  success: true;
  grantId: string;
  revokedAt: string; // ISO8601形式
}
```

**環境変数**:
- `OPENFGA_API_ENDPOINT`: OpenFGA API Gatewayエンドポイント
- `OPENFGA_STORE_ID`: OpenFGA Store ID

**IAMポリシー要件**:
- テナント専用DynamoDBテーブルへの読み書き権限（Query、UpdateItem、BatchWriteItem）
- OpenFGA API Gatewayへの実行権限（execute-api:Invoke）
- テナントロールのAssumeRole権限

**タイムアウト**: 30秒

**メモリ**: 512 MB

---

#### 1.2.3 権限チェックLambda関数 (`checkPermission.ts`)

**役割**: OpenFGAとDynamoDBに問い合わせて、ユーザが機能を使えるか判定する

**呼び出し元**: 各種機能を提供するAPI（Lambda関数呼び出し）

**入力パラメータ**:
```typescript
interface CheckPermissionRequest {
  tenantId: string;   // テナントID
  userId: string;     // ユーザID
  featureId: string;  // 機能ID
}
```

**処理内容**:
1. リクエストのバリデーション
2. OpenFGAに権限の有無を問い合わせ
   - `Check` APIを実行
   - リクエスト: `user:{userId}` can `can_access` `feature:{featureId}`
3. DynamoDBに利用回数の残数を問い合わせ
   - GetItemを実行（userId、featureId#periodをキーに取得）
   - 日次制限と月次制限の両方をチェック
   - currentCount < limitCountであれば残数あり
4. 両方の結果を総合して判定
   - OpenFGAで権限あり AND DynamoDBで残数あり → 許可
   - それ以外 → 拒否

**出力**:
```typescript
interface CheckPermissionResponse {
  allowed: boolean;
  reason?: string;  // 拒否理由（"no_permission" | "quota_exceeded"）
  usage?: {
    daily?: {
      current: number;
      limit: number;
      remaining: number;
    };
    monthly?: {
      current: number;
      limit: number;
      remaining: number;
    };
  };
}
```

**環境変数**:
- `OPENFGA_API_ENDPOINT`: OpenFGA API Gatewayエンドポイント
- `OPENFGA_STORE_ID`: OpenFGA Store ID

**IAMポリシー要件**:
- テナント専用DynamoDBテーブルへの読み取り権限（GetItem）
- OpenFGA API Gatewayへの実行権限（execute-api:Invoke）
- テナントロールのAssumeRole権限

**タイムアウト**: 10秒（高速な応答が必要）

**メモリ**: 256 MB

**備考**:
- この関数は頻繁に呼ばれるため、パフォーマンスが重要
- 将来的にはElastiCacheでのキャッシュ導入を検討

#### 1.2.4 カウント加算Lambda関数 (`incrementUsageCount.ts`)

**役割**: DynamoDBの利用回数カウンターを1増やす

**呼び出し元**: 機能を実際に使った直後（各種API）

**入力パラメータ**:
```typescript
interface IncrementUsageCountRequest {
  tenantId: string;   // テナントID
  userId: string;     // ユーザID
  featureId: string;  // 機能ID
  periodType: 'daily' | 'monthly';  // 期間タイプ
}
```

**処理内容**:
1. リクエストのバリデーション
2. DynamoDBのカウンターをアトミックに更新
   - UpdateItemを実行
   - `ADD currentCount 1`（アトミックカウンター）
   - updatedAtタイムスタンプを更新

**出力**:
```typescript
interface IncrementUsageCountResponse {
  success: true;
  newCount: number;  // 更新後のカウント値
}
```

**IAMポリシー要件**:
- テナント専用DynamoDBテーブルへの更新権限（UpdateItem）
- テナントロールのAssumeRole権限

**タイムアウト**: 5秒

**メモリ**: 256 MB

---

#### 1.2.5 カウントリセットLambda関数 (`resetUsageCount.ts`)

**役割**: DynamoDBの利用回数カウンターをゼロにリセットする

**呼び出し元**: EventBridge Schedulerから定期的に呼ばれる

**入力パラメータ**:
```typescript
interface ResetUsageCountRequest {
  periodType: 'daily' | 'monthly';  // 期間タイプ
}
```

**処理内容**:
1. 全テナントのリストを取得
   - テナントマネージャーから全テナントIDを取得
2. 各テナントのDynamoDBテーブルを処理
   - テナントロールをAssumeRoleして認証情報を取得
   - 利用回数カウントテーブルから該当期間タイプのアイテムを取得
     - periodType-indexを使用したQuery
   - 各アイテムのcurrentCountをゼロにリセット
     - BatchWriteItemで効率的に更新
   - nextResetTimeを次のリセット日時に更新
     - 日次: 翌日0時UTC
     - 月次: 翌月1日0時UTC
3. 処理結果をログに記録
   - 処理したテナント数、更新したアイテム数、エラー数

**出力**:
```typescript
interface ResetUsageCountResponse {
  success: true;
  processedTenants: number;
  updatedItems: number;
  errors: Array<{
    tenantId: string;
    error: string;
  }>;
}
```

**環境変数**:
- `TENANT_TABLE_NAME`: テナント管理テーブル名（中央管理）

**IAMポリシー要件**:
- 全テナントのDynamoDBテーブルへのアクセス権限（Query、BatchWriteItem）
- 全テナントロールのAssumeRole権限
- テナント管理テーブルへの読み取り権限（Scan）

**タイムアウト**: 15分（大量のテナントを処理する可能性があるため）

**メモリ**: 1024 MB

**備考**:
- 処理時間が長くなる場合は、Step Functionsでの並列処理を検討
- エラーが発生したテナントについてはCloudWatchアラートを発行

## 2. DynamoDBテーブル設計

### 2.1 利用回数カウントテーブル

**テーブル名**: `UsageCounter-{environment}-tenant-{sanitizedTenantId}`

**命名規則**: 既存のテナント専用DynamoDBテーブルと同じパターン

**主キー構成**:
- **パーティションキー**: `userId` (String) - ユーザID
- **ソートキー**: `featureIdPeriod` (String) - 機能IDと期間タイプの複合キー
  - 形式: `{featureId}#{periodType}`
  - 例: `feature-model-b#daily`

**属性**:
```typescript
interface UsageCounterItem {
  userId: string;              // ユーザID（パーティションキー）
  featureIdPeriod: string;     // 機能ID#期間タイプ（ソートキー）
  featureId: string;           // 機能ID（検索用）
  periodType: 'daily' | 'monthly';  // 期間タイプ（検索用）
  currentCount: number;        // 現在の利用回数
  limitCount: number;          // 上限回数
  nextResetTime: number;       // 次回リセット日時（Unixタイムスタンプ、秒単位）
  grantId: string;             // 権限付与ID（どの権限付与で追加されたか）
  createdAt: number;           // 作成日時（Unixタイムスタンプ、秒単位）
  updatedAt: number;           // 更新日時（Unixタイムスタンプ、秒単位）
}
```

**GSI (Global Secondary Index)**:

1. **grantId-index**
   - 目的: 権限剥奪時に該当する全てのカウンター情報を検索
   - パーティションキー: `grantId` (String)
   - 射影タイプ: ALL

2. **periodType-nextResetTime-index**
   - 目的: バッチリセット処理で期限が来たカウンターを効率的に検索
   - パーティションキー: `periodType` (String)
   - ソートキー: `nextResetTime` (Number)
   - 射影タイプ: ALL

**データ例**:
```json
{
  "userId": "user-123",
  "featureIdPeriod": "feature-model-b#daily",
  "featureId": "feature-model-b",
  "periodType": "daily",
  "currentCount": 30,
  "limitCount": 50,
  "nextResetTime": 1699747200,
  "grantId": "GRANT-456",
  "createdAt": 1699660800,
  "updatedAt": 1699700000
}
```

**Billing Mode**: PAY_PER_REQUEST（オンデマンド）

**Removal Policy**:
- 開発環境: DESTROY
- 本番環境: RETAIN

---

### 2.2 権限付与履歴テーブル

**テーブル名**: `PermissionGrant-{environment}-tenant-{sanitizedTenantId}`

**主キー構成**:
- **パーティションキー**: `grantId` (String) - 権限付与ID

**属性**:
```typescript
interface PermissionGrantItem {
  grantId: string;              // 権限付与ID（パーティションキー）
  userId: string;               // ユーザID
  features: Array<{             // 付与された機能のリスト
    featureId: string;
    limitType: 'unlimited' | 'daily' | 'monthly';
    limitCount?: number;
  }>;
  status: 'active' | 'revoked'; // 状態
  sourceType: string;           // 付与元のタイプ
  sourceId: string;             // 付与元のID
  grantedAt: number;            // 付与日時（Unixタイムスタンプ、秒単位）
  revokedAt?: number;           // 剥奪日時（Unixタイムスタンプ、秒単位）
}
```

**GSI (Global Secondary Index)**:

1. **userId-status-index**
   - 目的: ユーザIDと状態で検索（ユーザの現在有効な権限一覧を取得）
   - パーティションキー: `userId` (String)
   - ソートキー: `status` (String)
   - 射影タイプ: ALL

**データ例**:
```json
{
  "grantId": "GRANT-456",
  "userId": "user-123",
  "features": [
    {
      "featureId": "feature-a",
      "limitType": "unlimited"
    },
    {
      "featureId": "feature-b",
      "limitType": "daily",
      "limitCount": 50
    }
  ],
  "status": "active",
  "sourceType": "subscription",
  "sourceId": "sub-789",
  "grantedAt": 1699660800
}
```

**Billing Mode**: PAY_PER_REQUEST（オンデマンド）

**Removal Policy**:
- 開発環境: DESTROY
- 本番環境: RETAIN

## 3. OpenFGAとの連携

### 3.1 既存OpenFGA構成の利用

**既存リソース**:
- ECS Fargate Service（OpenFGAサーバー）
- PostgreSQL RDS（OpenFGAのデータストア）
- API Gateway（OpenFGAへの公開エンドポイント）

**アクセス方法**:
Lambda関数は、API Gateway経由でOpenFGAにアクセスします。IAM署名付きリクエストを使用してAPI Gatewayを呼び出します。

### 3.2 OpenFGA認可モデルの拡張

**既存モデルへの追加**:

```
type user
type feature

type user_feature_grant

```

**関係性の登録例**:

権限付与時:
```typescript
// WriteTuples APIを使用

  "writes": {

        "user": "user:user-123",
```

## 4. EventBridge Schedulerの設定

### 4.1 日次カウントリセット

**リソース名**: `DailyUsageCountReset-{environment}`

**スケジュール**: 毎日午前0時（UTC）

**Cron式**: `cron(0 0 * * ? *)`

**ターゲット**: `resetUsageCount` Lambda関数

**入力ペイロード**:
```json
{
  "periodType": "daily"
}
```

**リトライ設定**:
- 最大リトライ回数: 2
- リトライ間隔: 60秒

**デッドレターキュー**: 有効（失敗したイベントをSQSに送信）

---

### 4.2 月次カウントリセット

**リソース名**: `MonthlyUsageCountReset-{environment}`

**スケジュール**: 毎月1日の午前0時（UTC）

**Cron式**: `cron(0 0 1 * ? *)`

**ターゲット**: `resetUsageCount` Lambda関数

**入力ペイロード**:
```json
{
  "periodType": "monthly"
}
```

**リトライ設定**:
- 最大リトライ回数: 2
- リトライ間隔: 60秒

**デッドレターキュー**: 有効（失敗したイベントをSQSに送信）

## 5. CDK Constructの実装

### 5.1 ファイル配置

```
packages/cdk/lib/construct/
└── authorization-system.ts  # 権限判定システムのConstruct
```

### 5.2 Construct構成

**クラス名**: `AuthorizationSystem`

**主な責務**:
1. テナント専用DynamoDBテーブルの作成（利用回数カウント、権限付与履歴）
2. Lambda関数の作成（5つの関数）
3. EventBridge Schedulerの設定（日次・月次リセット）
4. IAMポリシーの設定（各Lambda関数に必要な権限）
5. 環境変数の設定（OpenFGAエンドポイント、Store ID）

**入力パラメータ**:
```typescript
interface AuthorizationSystemProps {
  tenantId: string;           // テナントID
  environment: string;        // 環境（dev, staging, prod）
  openFgaApiEndpoint: string; // OpenFGA API Gatewayエンドポイント
  openFgaStoreId: string;     // OpenFGA Store ID
  tenantRole: iam.IRole;      // テナントロール（クロスアカウントアクセス用）
}
```

**公開プロパティ**:
```typescript
class AuthorizationSystem extends Construct {
  public readonly grantPermissionFunction: lambda.Function;
  public readonly revokePermissionFunction: lambda.Function;
  public readonly checkPermissionFunction: lambda.Function;
  public readonly incrementUsageCountFunction: lambda.Function;
  public readonly resetUsageCountFunction: lambda.Function;
  public readonly usageCounterTable: dynamodb.Table;
  public readonly permissionGrantTable: dynamodb.Table;
}
```

**実装のポイント**:
- Lambda関数は`NodejsFunction`を使用（esbuildでのバンドル）
- DynamoDBテーブルは既存の`TenantDynamoDB`パターンを踏襲
- EventBridge Schedulerは`events.Rule`で実装
- IAMポリシーは最小権限の原則に従う

## 7. エラーハンドリングとリトライ

### 7.1 Lambda関数のエラーハンドリング

**方針**:
- 一時的なエラー（ネットワークエラー、タイムアウト）は自動リトライ
- 恒久的なエラー（バリデーションエラー、権限エラー）は即座に失敗を返す
- エラーログはCloudWatch Logsに詳細を記録

**実装パターン**:
```typescript
try {
  // 処理
} catch (error) {
  console.error('Error in grantPermission:', error);

  // 一時的なエラーかどうか判定
  if (isRetryableError(error)) {
    // Lambda関数の自動リトライに任せる（例外を再スロー）
    throw error;
  } else {
    // 恒久的なエラーはエラーレスポンスを返す
    return {
      statusCode: 400,
      body: JSON.stringify({
        error: 'VALIDATION_ERROR',
        message: error.message
      })
    };
  }
}
```

## 8. テナント間分離の実装

### 8.1 Lambda関数の実行ロール

**方針**:
- Lambda関数は共通の実行ロールを持つ
- 全テナントのDynamoDBテーブルとテナントロールへのアクセス権限を付与
- 実行時にテナントIDに基づいてテナントロールをAssumeRoleして認証情報を取得

**IAMポリシー**:
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "sts:AssumeRole",
      "Resource": "arn:aws:iam::*:role/TenantRole-*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "dynamodb:GetItem",
        "dynamodb:PutItem",
        "dynamodb:UpdateItem",
        "dynamodb:Query",
        "dynamodb:BatchWriteItem"
      ],
      "Resource": "arn:aws:dynamodb:*:*:table/*-tenant-*"
    },
    {
      "Effect": "Allow",
      "Action": "execute-api:Invoke",
      "Resource": "arn:aws:execute-api:*:*:*/prod/*"
    }
  ]
}
```

### 9.1 CloudWatch Metricsの記録

**カスタムメトリクス**:
- `PermissionGrantCount`: 権限付与回数（Dimensions: TenantId）
- `PermissionRevokeCount`: 権限剥奪回数（Dimensions: TenantId）
- `PermissionCheckCount`: 権限チェック回数（Dimensions: TenantId, FeatureId）
- `PermissionDeniedCount`: 権限拒否回数（Dimensions: TenantId, FeatureId, Reason）
- `UsageCountIncrementCount`: カウント加算回数（Dimensions: TenantId, FeatureId）

**実装**:
```typescript
import { CloudWatchClient, PutMetricDataCommand } from '@aws-sdk/client-cloudwatch';

const cloudwatch = new CloudWatchClient();

async function recordMetric(metricName: string, value: number, dimensions: Record<string, string>) {
  await cloudwatch.send(new PutMetricDataCommand({
    Namespace: 'AuthorizationSystem',
    MetricData: [{
      MetricName: metricName,
      Value: value,
      Unit: 'Count',
      Dimensions: Object.entries(dimensions).map(([Name, Value]) => ({ Name, Value })),
      Timestamp: new Date()
    }]
  }));
}
```

## 10. パフォーマンス最適化

### 10.1 DynamoDBの最適化

**戦略**:
- オンデマンドモードを使用（負荷に応じて自動スケーリング）
- GSIの射影タイプをALLに設定（追加のGetItem不要）
- BatchWriteItemで一括削除（権限剥奪時）

### 10.2 Lambda関数の最適化

**戦略**:
- メモリサイズの調整（権限チェック関数は256MB、その他は512MB）
- esbuildでのバンドル（依存関係の最小化）
- AWS SDK v3のモジュラーインポート（必要なクライアントのみ）
- 環境変数でのキャッシュ（OpenFGAエンドポイント、Store IDなど）

### 10.3 将来的な最適化（検討事項）

**検討事項**:
1. **ElastiCacheでの権限チェック結果のキャッシュ**
   - TTL: 60秒
   - 頻繁にアクセスされる権限チェック結果をキャッシュ
   - キャッシュミス時はOpenFGAとDynamoDBに問い合わせ

2. **DynamoDB Streamsでの非同期処理**
   - カウント加算を非同期化
   - Kinesisでのバッファリング

3. **Lambda関数のProvisioned Concurrency**
   - 権限チェック関数のコールドスタート削減
