## 検証目的
ヘッダー名を`stripe-signature`（小文字）から`Stripe-Signature`（大文字）に修正後、Webhookイベントの署名検証が正常に動作し、以降の処理フロー（DynamoDB保存、EventBridge送信）が実行されることを確認する。

## 前回の問題
- Stripeは`Stripe-Signature`（大文字のS）というヘッダー名で署名を送信
- コードでは`event.headers['stripe-signature']`（小文字のs）でアクセスしていた
- そのため、署名が`undefined`になり、400エラーで処理が終了していた

## 実施した修正
[receiveWebhook.ts:89](../../packages/cdk/lambda/billing/payment-gateway/webhook/stripe/receiveWebhook.ts#L89)を修正：
```typescript
// 修正前
const signature = event.headers['stripe-signature'];

// 修正後
const signature = event.headers['Stripe-Signature'];
```

### 5. WebhookEventRepositoryコードの確認

[webhookEventRepository.ts:34-38](../../packages/cdk/lambda/billing/payment-gateway/repositories/webhookEventRepository.ts#L34-L38)を確認：

```typescript
async findByEventId(eventId: string): Promise<WebhookEvent | null> {
  const command = new GetItemCommand({
    TableName: this.tableName,
    Key: marshall({ event_id: eventId }),  // ← event_idのみを指定
  });
```

**問題の特定:**
- `GetItemCommand`を使用する場合、DynamoDBの複合キーテーブルでは**両方のキー属性（HASHとRANGE）を指定する必要がある**
- しかし、コードでは`event_id`のみを指定しており、`received_at`が欠けている
- そのため、`ValidationException: The provided key element does not match the schema`エラーが発生している

**根本原因:**
テーブル設計とリポジトリコードの不整合：
- テーブルは`event_id` + `received_at`の複合キーを期待
- リポジトリは`event_id`だけでアイテムを取得しようとしている

   - 修正: [receiveWebhook.ts:89](../../packages/cdk/lambda/billing/payment-gateway/webhook/stripe/receiveWebhook.ts#L89)を`event.headers['Stripe-Signature']`に変更

   - 影響: 重複チェック処理でエラーが発生し、以降の処理（イベント保存、EventBridge送信）が実行されない
   - エラー: `ValidationException: The provided key element does not match the schema`

## 次のステップ（修正が必要な項目）

### 推奨される修正方法

以下の2つのアプローチが考えられます：

#### アプローチ1: テーブルスキーマをシンプルキーに変更
- HASH キーのみ（`event_id`）のテーブルに変更
- メリット: リポジトリコードの変更が不要
- デメリット: 既存のテーブル構造を変更する必要がある

#### アプローチ2: リポジトリコードを修正（推奨）
- `findByEventId`メソッドを`QueryCommand`を使用する方式に変更
- `event_id`のみをパーティションキーとして検索
- メリット: テーブル構造を変更する必要がない
- デメリット: リポジトリコードの修正が必要

**推奨:** アプローチ2（リポジトリコードの修正）

理由：
- Webhookイベントの重複チェックには`event_id`だけで十分（Stripeのイベントは一意のIDを持つ）
- `received_at`をRANGEキーとして持つことで、時系列での検索が効率的になる設計意図がある
- `GetItemCommand`の代わりに`QueryCommand`を使用すればコードの変更のみで対応可能

### 修正案

[webhookEventRepository.ts:34-47](../../packages/cdk/lambda/billing/payment-gateway/repositories/webhookEventRepository.ts#L34-L47)を以下のように修正：

```typescript
async findByEventId(eventId: string): Promise<WebhookEvent | null> {
  const command = new QueryCommand({
    TableName: this.tableName,
    KeyConditionExpression: 'event_id = :event_id',
    ExpressionAttributeValues: marshall({
      ':event_id': eventId,
    }),
    Limit: 1,
  });

  const result = await this.client.send(command);

  if (!result.Items || result.Items.length === 0) {
    return null;
  }

  return unmarshall(result.Items[0]) as WebhookEvent;
}
```
