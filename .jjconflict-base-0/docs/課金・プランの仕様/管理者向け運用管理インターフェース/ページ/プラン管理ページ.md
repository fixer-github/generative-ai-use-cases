# プラン管理ページ

## ページの概要

このページは、システムで提供するすべてのプラン（FreeプランやStandardプランなど）を管理するためのページです。管理者は、このページで新しいプランを作成したり、既存のプランの情報を確認したり、プランの提供状態を変更したりできます。

**ページのURL**: `/admin/billing/plans`

**利用できる人**: 管理者ロールを持つユーザのみ

---

## このページで何ができるのか

### 1. プラン一覧を見る

システムに登録されているすべてのプランの情報を一覧形式で確認できます。

**一覧に表示される情報**:
- **プランID**: システムが各プランに自動的に割り当てる識別番号です。例えば「123e4567-e89b-12d3-a456-426614174000」のような形式です
- **内部名称**: 管理者がプランを見分けるための名前です。例えば「standard_2025_jan_stripe」のように、プランの種類、作成時期、課金プラットフォームが分かる名前が付けられています
- **表示名**: ユーザに見せるプランの名前です。例えば「Standardプラン」「Proプラン」のように、分かりやすい名前が設定されています
- **プラットフォーム種別**: このプランがどの課金の仕組みで提供されるかを示します
  - 「stripe」: Webサイトでクレジットカード決済をする仕組み
  - 「apple」: iPhoneやiPadのアプリ内で購入する仕組み
  - 「google」: Androidアプリ内で購入する仕組み
  - 「internal」: 課金を伴わないプラン（Freeプランや、管理者が特別に付与するプランなど）
- **ステータス**: プランの現在の状態を示します
  - 「active」: 新しいユーザが加入できる状態
  - 「closed_to_new」: 既に加入している人は継続できるが、新しい人は加入できない状態
  - 「deprecated」: 提供を終了した状態（加入者がゼロ人になった後に設定）
- **作成日時**: このプランがいつシステムに登録されたかを示す日時です

**並び替え機能**:
- 作成日時の新しい順/古い順
- 内部名称のアルファベット順
- ステータス別

**絞り込み機能**:
- プラットフォーム種別で絞り込み（例: Stripeのプランだけを表示）
- ステータスで絞り込み（例: 現在新規加入できるプランだけを表示）
- 内部名称や表示名で検索（部分一致）

### 2. プランの詳細を見る

一覧から特定のプランを選ぶと、そのプランの詳しい情報が表示されます。

**詳細画面に表示される情報**:

#### 基本情報
- プランID
- 内部名称
- 表示名
- 説明文（ユーザに見せるプランの説明）
- プラットフォーム種別
- ステータス
- 作成日時
- 最終更新日時

#### プラットフォーム連携情報
- **プラットフォーム商品ID**: 課金の仕組み（StripeやAppleなど）側で作成された商品の識別番号です
  - Stripeの場合: 「price_xxxxx」という形式
  - Appleの場合: 「com.example.standard_monthly」のような形式
  - Googleの場合: 「standard_monthly」のような形式
  - internalの場合: 空欄

#### 権限・制限定義
このプランに加入したユーザが「何ができるか」と「何回まで使えるか」を定義した情報です。JSON形式で保存されており、詳細画面では分かりやすい形で表示されます。

**表示例**:
```
利用可能な機能:
・機能A
・機能B
・機能C

利用回数の制限:
・モデルA: 無制限
・モデルB: 1日あたり100回まで
・モデルC: 1ヶ月あたり400回まで
```

この情報は、元のJSON形式でも確認できます（技術的な確認が必要な場合に便利です）。

#### 契約状況
- **現在の契約者数**: 現在このプランに加入しているユーザの人数
  - サブスクリプション経由の契約数
  - トライアルでの利用者数
  - 手動付与での利用者数
  - それぞれの内訳も確認できます

### 3. 新しいプランを作る

新しいプランを作成するための入力フォームを開き、必要な情報を入力してプランを登録できます。

**入力する項目**:

#### 必須項目
1. **内部名称**（文字列、最大255文字）
   - 管理者が識別しやすい名前を付けます
   - 推奨される命名規則: 「プラン種別_作成年月_プラットフォーム」
   - 例: 「standard_2025_jan_stripe」「pro_2025_feb_ios」
   - 同じ名前は使えません（重複不可）

2. **表示名**（文字列、最大255文字）
   - ユーザに見せる名前を設定します
   - 例: 「Standardプラン」「Proプラン」

3. **プラットフォーム種別**（選択式）
   - 以下から1つを選びます:
     - stripe: Stripe Billing経由
     - apple: Apple App Store経由
     - google: Google Play Store経由
     - internal: 課金プラットフォームを経由しない

4. **権限・制限定義**（JSON形式）
   - 利用可能な機能と回数制限を定義します
   - 入力補助ツールを使って、視覚的に設定できるようになっています
   - 例:
     ```json
     {
       "features": ["feature_a", "feature_b", "feature_c"],
       "limits": {
         "model_a": {
           "type": "unlimited"
         },
         "model_b": {
           "type": "daily",
           "count": 100
         },
         "model_c": {
           "type": "monthly",
           "count": 400
         }
       }
     }
     ```

#### 任意項目
5. **説明**（テキスト）
   - プランの詳しい説明を記入します
   - ユーザに表示される説明文として使います
   - 空欄でも構いません

6. **プラットフォーム商品ID**（文字列、最大255文字）
   - Stripe、Apple、Googleなど、課金プラットフォーム側で作成した商品IDを入力します
   - プラットフォーム種別が「internal」の場合は不要です
   - 例:
     - Stripe: 「price_1234567890」
     - Apple: 「com.example.standard_monthly」
     - Google: 「standard_monthly」

**入力フォームの補助機能**:
- **権限・制限定義の入力支援**: JSON形式を直接書かなくても、フォームから選択・入力できるツールが用意されています
  - 機能の追加/削除ボタン
  - モデルごとの制限設定（無制限、日次、月次から選択）
  - プレビュー表示（入力内容がJSON形式でどう見えるか確認できる）
- **バリデーション（入力内容の検証）**: 入力内容に問題がないかを自動的にチェックします
  - 内部名称の重複チェック
  - JSON形式の正しさチェック
  - プラットフォーム商品IDの形式チェック
  - 必須項目の入力漏れチェック

**プラン作成の流れ**:
1. 「新しいプランを作成」ボタンをクリックします
2. 入力フォームが表示されます
3. 必要な情報を入力します
4. 「プレビュー」ボタンで入力内容を確認できます
5. 「作成」ボタンをクリックします
6. 入力内容が検証されます（問題があればエラーメッセージが表示されます）
7. 問題がなければ、新しいプランが作成されます
8. 作成したプランの詳細画面に移動します

**作成時の初期ステータス**:
- 新しく作成されたプランは、自動的に「active」（新規加入可能）の状態になります
- 必要に応じて、後からステータスを変更できます

### 4. プランのステータスを変更する

既存のプランの提供状態を変更できます。ただし、以下のルールに従って変更する必要があります。

**ステータスの遷移ルール**:
- 「active」から「closed_to_new」へ変更できます
- 「closed_to_new」から「deprecated」へ変更できます
- 逆方向への変更（例: closed_to_newからactiveへ戻す）はできません

これは、既に加入しているユーザの権利を保護するためのルールです。

**各ステータスの意味と影響**:

#### active（新規加入可能）
- **意味**: 新しいユーザがこのプランに加入できる状態です
- **新規加入**: 可能
- **既存契約の継続**: 可能
- **プラン変更での選択**: 可能

#### closed_to_new（新規受付終了）
- **意味**: 既に加入している人は継続できますが、新しい人は加入できない状態です。これを「グランドファザリング」と呼びます
- **新規加入**: 不可能
- **既存契約の継続**: 可能
- **プラン変更での選択**: 不可能（既に加入している人だけが継続できる）

このステータスに変更する理由の例:
- プランの内容を変更したいが、既存のユーザには今の条件で使い続けてほしい場合
- プランを段階的に廃止したい場合

#### deprecated（廃止済み）
- **意味**: 提供を完全に終了した状態です
- **新規加入**: 不可能
- **既存契約の継続**: 不可能（すでに加入者がゼロ人の状態でのみ設定可能）
- **変更の条件**: 現在の契約者数がゼロ人であることが必要です

**ステータス変更の流れ**:
1. プラン詳細画面を開きます
2. 現在のステータスが表示されています
3. 「ステータスを変更」ボタンをクリックします
4. 変更可能なステータスが選択肢として表示されます（遷移ルールに従って、選べるステータスだけが表示されます）
5. 変更先のステータスを選びます
6. 確認画面が表示されます
   - 変更内容の要約
   - 変更による影響の説明（新規加入が不可能になる、など）
   - 現在の契約者数（deprecatedに変更する場合は、ゼロ人であることを確認）
7. 「変更を実行」ボタンをクリックします
8. ステータスが変更されます
9. 変更履歴が記録されます（誰がいつ変更したか）

**ステータス変更時の制約**:
- closed_to_newからdeprecatedへの変更は、現在の契約者数がゼロ人の場合のみ可能です
- 契約者がまだいる状態でdeprecatedに変更しようとすると、エラーメッセージが表示されます:
  「このプランには現在〇〇人の契約者がいるため、廃止できません。すべての契約が終了してから廃止してください。」

## 画面の構成要素

### 一覧画面の構成

#### ヘッダー部分
- ページタイトル: 「プラン管理」
- 「新しいプランを作成」ボタン（右上に配置）

#### 検索・絞り込みエリア
- テキスト検索ボックス（内部名称、表示名で検索）
- プラットフォーム種別の絞り込み（ドロップダウン選択）
- ステータスの絞り込み（ドロップダウン選択）
- 「検索」ボタン
- 「リセット」ボタン（絞り込み条件をクリア）

#### 統計情報エリア（一覧の上部に表示）
- 全プラン数: 〇〇件
- active状態のプラン数: 〇〇件
- closed_to_new状態のプラン数: 〇〇件
- deprecated状態のプラン数: 〇〇件

#### テーブル（一覧表）
- 列構成:
  - プランID（短縮表示、ホバーで全体を表示）
  - 内部名称（クリック可能、詳細画面へのリンク）
  - 表示名
  - プラットフォーム種別（バッジ表示で色分け）
  - ステータス（バッジ表示で色分け）
  - 作成日時
  - アクション（「詳細を見る」ボタン）
- ページネーション（1ページあたり20件表示）
- ソート機能（各列のヘッダーをクリックして昇順/降順を切り替え）

### 詳細画面の構成

#### ヘッダー部分
- ページタイトル: プランの内部名称
- パンくずリスト: プラン管理 > プラン詳細
- 「一覧に戻る」ボタン
- 「ステータスを変更」ボタン

#### タブ構成
詳細画面は、情報を整理するためにタブで分けて表示します。

**タブ1: 基本情報**
- プランID
- 内部名称
- 表示名
- 説明
- プラットフォーム種別
- プラットフォーム商品ID
- ステータス（バッジ表示）
- 作成日時
- 最終更新日時

**タブ2: 権限・制限定義**
- 分かりやすい表示形式:
  - 利用可能な機能のリスト
  - 各モデルの利用制限（表形式で表示）
- 元のJSON形式表示（展開/折りたたみ可能）
- 「コピー」ボタン（JSON内容をクリップボードにコピー）

**タブ3: 契約状況**
- 現在の契約者数（合計）
- 契約種別ごとの内訳:
  - サブスクリプション経由: 〇〇人
  - トライアル: 〇〇人
  - 手動付与: 〇〇人
  - デフォルトプラン: 〇〇人
  - キャンペーン: 〇〇人
- プラットフォーム別の内訳（該当する場合）
- 契約者の傾向グラフ（過去30日間の推移）

**タブ4: 変更履歴**
- このプランに対して行われた変更の履歴
  - 変更日時
  - 変更を行った管理者
  - 変更内容（例: 「ステータスをactiveからclosed_to_newに変更」）

### プラン作成フォーム画面の構成

#### ヘッダー部分
- ページタイトル: 「新しいプランを作成」
- パンくずリスト: プラン管理 > 新規作成
- 「キャンセル」ボタン

#### フォームエリア

**セクション1: 基本情報**
- 内部名称（テキスト入力、必須）
  - 入力例の表示: 「例: standard_2025_jan_stripe」
  - リアルタイムバリデーション（重複チェック）
- 表示名（テキスト入力、必須）
  - 入力例の表示: 「例: Standardプラン」
- 説明（テキストエリア、任意）
  - 複数行入力可能

**セクション2: プラットフォーム設定**
- プラットフォーム種別（ラジオボタンまたはドロップダウン、必須）
  - stripe
  - apple
  - google
  - internal
- プラットフォーム商品ID（テキスト入力、条件付き必須）
  - プラットフォーム種別が「internal」以外の場合は必須
  - 入力例の表示:
    - Stripeの場合: 「例: price_1234567890」
    - Appleの場合: 「例: com.example.standard_monthly」
    - Googleの場合: 「例: standard_monthly」

**セクション3: 権限・制限定義**
- 入力方法の選択:
  - 「フォームで入力」（初期選択、分かりやすい）
  - 「JSONを直接入力」（上級者向け）

「フォームで入力」を選択した場合:
- 利用可能な機能の設定:
  - 機能の一覧が表示され、チェックボックスで選択
  - 新しい機能を追加するボタン
- 利用回数の制限設定:
  - モデルごとに設定を追加できる
  - 各モデルの設定項目:
    - モデルの種類（ドロップダウン）
    - 制限の種類（ラジオボタン: 無制限、日次制限、月次制限）
    - 制限回数（数値入力、制限ありの場合のみ）
  - 「モデルを追加」ボタン
  - 「モデルを削除」ボタン

「JSONを直接入力」を選択した場合:
- JSONエディタ（シンタックスハイライト付き）
- リアルタイムバリデーション（JSON形式のチェック）

- プレビュー表示エリア:
  - 入力内容が実際のJSON形式でどう表現されるかを表示
  - 「フォームで入力」「JSONを直接入力」どちらの方法でも、同じプレビューが表示される

#### フッター部分
- 「プレビュー」ボタン（入力内容の最終確認画面を表示）
- 「作成」ボタン（プランを作成）
- 「キャンセル」ボタン（入力内容を破棄して一覧に戻る）

### ステータス変更画面の構成

#### 現在の状態表示
- 現在のステータス（大きくバッジ表示）
- 現在の契約者数
- ステータスの意味の説明

#### 変更先の選択
- 変更可能なステータスのみがボタンとして表示される
- 各ステータスを選ぶと、詳しい説明が表示される:
  - このステータスに変更すると何が起こるか
  - 新規加入や既存契約への影響
  - 注意事項

#### 確認と実行
- 「変更内容の確認」エリア:
  - 変更前のステータス
  - 変更後のステータス
  - 影響を受ける契約数（該当する場合）
- 確認チェックボックス: 「変更内容を理解し、実行することに同意します」
- 「変更を実行」ボタン（チェックボックスにチェックが入るまで無効化）
- 「キャンセル」ボタン

## 管理者が行える操作の具体例

### 例1: 新しいStandardプランを作成する

**状況**:
2025年1月から、Web版でクレジットカード決済できる新しいStandardプランを提供したいと考えています。

**操作の流れ**:

1. プラン管理ページ（/admin/billing/plans）を開きます
2. 右上の「新しいプランを作成」ボタンをクリックします
3. 入力フォームが表示されるので、以下の情報を入力します:
   - 内部名称: 「standard_2025_jan_stripe」
   - 表示名: 「Standardプラン」
   - 説明: 「モデルAとBに無制限アクセス。モデルCは月400回まで利用可能。」
   - プラットフォーム種別: 「stripe」を選択
   - プラットフォーム商品ID: 「price_1234567890」（Stripeで事前に作成した価格ID）
   - 権限・制限定義:
     - 利用可能な機能: feature_a、feature_b、feature_cにチェック
     - モデルAの制限: 「無制限」を選択
     - モデルBの制限: 「無制限」を選択
     - モデルCの制限: 「月次制限」を選択、回数に「400」を入力
4. 「プレビュー」ボタンをクリックして、入力内容を確認します
5. 問題がなければ「作成」ボタンをクリックします
6. プランが作成され、詳細画面に移動します
7. ステータスが「active」になっており、新規ユーザが加入できる状態になっています

**結果**:
新しいStandardプランが作成され、Webサイトでクレジットカード決済を選んだユーザがこのプランに加入できるようになりました。

### 例2: 古いプランを新規受付終了にする

**状況**:
2024年版のStandardプランの内容を変更したいのですが、既に加入している人には今の条件で使い続けてもらいたいと考えています。そのため、古いプランは新規受付を終了し、新しいプランを作成することにしました。

**操作の流れ**:

1. プラン管理ページ（/admin/billing/plans）を開きます
2. 検索ボックスに「standard_2024」と入力して、古いプランを検索します
3. 該当するプランの「詳細を見る」ボタンをクリックします
4. 詳細画面が表示されます。現在のステータスは「active」です
5. 「契約状況」タブを開いて、現在の契約者数を確認します（例: 150人）
6. 「ステータスを変更」ボタンをクリックします
7. 変更先として「closed_to_new（新規受付終了）」を選びます
8. 説明が表示されます:
   「このステータスに変更すると:
   - 新しいユーザはこのプランに加入できなくなります
   - 既に加入している150人のユーザは、今まで通りこのプランを使い続けられます
   - 他のプランから変更する際にも、このプランは選択肢に表示されなくなります」
9. 確認チェックボックスにチェックを入れます
10. 「変更を実行」ボタンをクリックします
11. ステータスが「closed_to_new」に変更されます

**結果**:
古いStandardプランは新規受付を終了しましたが、既に加入している150人のユーザは今まで通り使い続けられます。新しいユーザには、別途作成した新しいStandardプランが提供されます。

### 例3: 契約者がいなくなったプランを廃止する

**状況**:
新規受付を終了していた古いプランの契約者が、全員他のプランに移行するか解約して、契約者数がゼロ人になりました。このプランを完全に廃止したいと考えています。

**操作の流れ**:

1. プラン管理ページ（/admin/billing/plans）を開きます
2. ステータスの絞り込みで「closed_to_new」を選択します
3. 該当するプランの「詳細を見る」ボタンをクリックします
4. 「契約状況」タブを開いて、現在の契約者数を確認します（0人であることを確認）
5. 「ステータスを変更」ボタンをクリックします
6. 変更先として「deprecated（廃止済み）」を選びます
7. 説明が表示されます:
   「このステータスに変更すると:
   - このプランは完全に廃止され、システムから削除される扱いになります
   - 現在の契約者数が0人であることを確認してください
   - この操作は取り消せません」
8. 現在の契約者数が0人であることが表示されます
9. 確認チェックボックスにチェックを入れます
10. 「変更を実行」ボタンをクリックします
11. ステータスが「deprecated」に変更されます

**結果**:
プランが完全に廃止され、システム内では提供終了の扱いになりました。ただし、過去の記録として情報は残っており、いつどのプランが提供されていたかを後から確認できます。

### 例4: プランの契約者数を確認する

**状況**:
現在提供中のProプランに何人が加入しているか、また、どのような経路で加入しているかを確認したいと考えています。

**操作の流れ**:

1. プラン管理ページ（/admin/billing/plans）を開きます
2. 検索ボックスに「pro」と入力して、Proプランを検索します
3. 該当するプランの「詳細を見る」ボタンをクリックします
4. 詳細画面の「契約状況」タブを開きます
5. 以下の情報が表示されます:
   - 現在の契約者数（合計）: 320人
   - 契約種別ごとの内訳:
     - サブスクリプション経由: 300人
       - Stripe経由: 180人
       - Apple経由: 80人
       - Google経由: 40人
     - トライアル: 15人
     - 手動付与: 5人
   - 契約者の傾向グラフ: 過去30日間で徐々に増加していることが分かります

**結果**:
Proプランには合計320人が加入しており、そのほとんどがサブスクリプション経由であることが分かりました。また、Stripe経由が最も多いことも確認できました。

### 例5: iOS向けの新しいプランを作成する

**状況**:
iPhoneアプリでも課金を開始することになりました。Apple App Store向けのStandardプランを作成する必要があります。

**操作の流れ**:

1. プラン管理ページ（/admin/billing/plans）を開きます
2. 「新しいプランを作成」ボタンをクリックします
3. 入力フォームで以下の情報を入力します:
   - 内部名称: 「standard_2025_jan_ios」
   - 表示名: 「Standardプラン」
   - 説明: Web版と同じ説明文を入力
   - プラットフォーム種別: 「apple」を選択
   - プラットフォーム商品ID: 「com.example.standard_monthly」（Apple側で作成した商品ID）
   - 権限・制限定義: 既存のStandardプラン（Stripe版）と同じ内容を設定
     - 既存のStandardプランの詳細画面を別タブで開き、「権限・制限定義」タブからJSONをコピー
     - 「JSONを直接入力」を選択して、コピーしたJSONを貼り付け
4. 「プレビュー」ボタンで内容を確認します
5. 「作成」ボタンをクリックします
6. プランが作成されます

**結果**:
iOSアプリ向けのStandardプランが作成されました。Web版のStandardプランと同じ権限・制限を持ちながら、課金の仕組みだけがApple App Storeになっています。ユーザがiPhoneアプリで購入操作を行うと、このプランが適用されます。

## セキュリティと制限

### アクセス制限

このページにアクセスできるのは、OpenFGAで「管理者」ロールを持つと認められたユーザのみです。

**アクセス時の認証フロー**:
1. ユーザがページを開こうとします
2. システムがOpenFGAに「このユーザは管理者ですか？」と問い合わせます
3. 管理者であればページが表示されます
4. 管理者でなければ、エラー画面が表示され、アクセスが拒否されます

### 操作の記録

管理者が行ったすべての操作は、監査ログとして記録されます。

**記録される情報**:
- 操作を行った管理者のユーザID
- 操作を行った日時
- 操作の種類（プラン作成、ステータス変更など）
- 操作の対象（どのプランに対する操作か）
- 操作の内容（変更前と変更後の値）
- 操作を行ったIPアドレス

この記録は後から確認でき、「誰がいつ何をしたか」を追跡できるようになっています。

### 入力値の検証

管理者が入力する情報は、保存する前に厳密にチェックされます。

**チェック項目**:
- 必須項目が入力されているか
- 文字数の制限を超えていないか
- JSON形式が正しいか
- プラットフォーム商品IDの形式が正しいか
- 内部名称が重複していないか
- 権限・制限定義の構造が正しいか（必須フィールドが含まれているか、など）

問題がある場合は、分かりやすいエラーメッセージが表示され、修正を促します。

### 削除操作の制限

プランは一度作成したら、基本的に削除できません。これは以下の理由によります:

1. **過去の記録を残す**: どのユーザが過去にどのプランを使っていたかの記録を残すため
2. **データの整合性**: プランを削除すると、過去のサブスクリプション情報との関連が壊れてしまうため
3. **監査の要件**: 後から「このプランはどんな内容だったか」を確認できるようにするため

提供を終了したい場合は、削除するのではなく、ステータスを「closed_to_new」や「deprecated」に変更します。

## エラー処理と通知

### よくあるエラーとその対処方法

#### エラー1: 「この内部名称は既に使われています」

**原因**: 同じ内部名称のプランが既に存在しています

**対処方法**: 別の内部名称を考えて入力してください。例えば、末尾にバージョン番号や日付を追加する方法があります

**例**:
- 既存: 「standard_2025_jan_stripe」
- 新しく入力: 「standard_2025_jan_stripe_v2」

#### エラー2: 「JSON形式が正しくありません」

**原因**: 権限・制限定義のJSONに書式エラーがあります

**対処方法**:
- 「フォームで入力」モードに切り替えて、視覚的に設定し直してください
- または、JSONエディタのエラーメッセージを確認して、問題の箇所を修正してください

#### エラー3: 「このプランには現在〇〇人の契約者がいるため、廃止できません」

**原因**: 契約者がまだ残っている状態で、ステータスを「deprecated」に変更しようとしました

**対処方法**:
- すべての契約者が他のプランに移行するか、契約を終了するまで待ってください
- または、ステータスを「closed_to_new」のままにして、将来的に契約者がゼロになった時点で廃止してください

#### エラー4: 「プラットフォーム商品IDの形式が正しくありません」

**原因**: 入力したプラットフォーム商品IDが、選択したプラットフォーム種別の形式と一致していません

**対処方法**:
- Stripeの場合: 「price_」で始まるIDを入力してください
- Appleの場合: 逆ドメイン形式（com.example.xxx）のIDを入力してください
- Googleの場合: アンダースコアを含む形式のIDを入力してください
- 課金プラットフォーム側で正しいIDを確認してから、再度入力してください

### 成功時の通知

操作が成功した際は、画面上部に成功メッセージが表示されます。

**表示される成功メッセージの例**:
- 「プランを作成しました」
- 「ステータスをclosed_to_newに変更しました」
- 「プランの情報を更新しました」

メッセージは数秒後に自動的に消えます。

## パフォーマンスと表示速度

### ページネーション

プラン一覧は、1ページあたり20件ずつ表示されます。これにより、プランの数が増えても表示速度が遅くならないようにしています。

ページの下部に、以下のナビゲーションが表示されます:
- 「前へ」ボタン
- ページ番号（1、2、3...）
- 「次へ」ボタン
- 「〇〇件中△△-□□件を表示」という表示

### データの読み込み

プラン一覧を開いた際、以下の順序でデータが読み込まれます:

1. 最初に統計情報（全プラン数など）が表示されます
2. 次に、最初のページのプラン一覧が表示されます
3. 詳細画面を開くと、そのプランの情報だけが読み込まれます

この仕組みにより、必要な情報だけを必要な時に読み込むことで、表示速度を速く保っています。
