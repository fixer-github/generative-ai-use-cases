## 「最低限動く状態」に不足している部分

### P0（動作させるために必須）

| 不足項目                     | 内容                                              | 影響                                           |
| ---------------------------- | ------------------------------------------------- | ---------------------------------------------- |
| **EventBridgeルール設定**    | Webhook→WebhookEventFlowへのルーティング、DLQ設定 | Webhookイベントが業務フローに到達しない        |
| **バッチ処理スケジューラー** | 定期同期・期限切れチェック・カウンターリセット    | サブスク更新反映されない、期限切れても権限残る |

## 具体的に「これやってない」リスト

### 1. Webhookイベント配信層がない

Stripe Webhookを受信しても、EventBridgeでオーケストレーションにルーティングする仕組みがない。

**必要な実装:**

- EventBridge イベントバス定義
- イベント種別ごとのルール（payment.succeeded, subscription.canceled等）
- DLQ（デッドレターキュー）設定
- リトライ制御（指数バックオフ）

### 2. 定期バッチが全くない

ドキュメントの「3. サブスクリプション状態同期」に記載されている以下が未実装:

- **毎日のサブスク状態同期**: プラットフォーム↔DB状態比較
- **期限切れプラン適用の自動終了**: `scheduled_termination`状態の処理
- **日次/月次の利用回数カウンターリセット**

**必要な実装:**

```
packages/cdk/lambda/billing/batch/
├── subscriptionSyncBatch.ts     # 毎日0時実行
├── expiredPlanCheckBatch.ts     # 毎日1時実行
└── counterResetBatch.ts         # 毎日0時（日次）、毎月初（月次）
```

### 3. Apple/Google連携が空実装

以下のファイルの中身が未実装:

- `packages/cdk/lambda/billing/payment-gateway/verification/appleVerifier.ts`
- `packages/cdk/lambda/billing/payment-gateway/verification/googleVerifier.ts`
- `packages/cdk/lambda/billing/payment-gateway/webhook/apple/receiveNotification.ts`
- `packages/cdk/lambda/billing/payment-gateway/webhook/google/receiveNotification.ts`

**必要な実装:**

- Apple App Store Server API呼び出し（レシート検証）
- Google Play Developer API呼び出し（レシート検証）
- Apple Server Notification受信・処理
- Google Real-time Developer Notification受信・処理

### 4. ユーザ向けに解約/変更APIがない

購入はできるが、解約やプラン変更をユーザが実行するAPIが公開されていない。

**必要な実装:**

```
packages/cdk/lambda/billing/user-api/subscriptions/
├── cancelSubscription.ts        # 解約API
├── changeSubscriptionPlan.ts    # プラン変更API
└── getInvoices.ts               # 請求書一覧取得API
```

### 5. 通知がない

購入完了、支払い失敗、解約確認などの通知がユーザに届かない。
障害発生時に管理者にアラートが飛ばない。

**必要な実装:**

```
packages/cdk/lambda/billing/notification/
├── sendUserNotification.ts      # ユーザ向け通知送信
├── sendAdminAlert.ts            # 管理者向けアラート送信
├── templates/                   # 通知テンプレート
│   ├── purchaseComplete.ts
│   ├── paymentFailed.ts
│   ├── cancellationConfirm.ts
│   └── trialExpiring.ts
└── channels/
    ├── emailSender.ts           # AWS SES連携
    ├── pushNotificationSender.ts # FCM連携
    └── slackSender.ts           # Slack連携（管理者向け）
```

## 次のアクション提案

「最低限動く」を達成するための優先順位:

### Phase 1: Stripeのみで最小動作確認

1. **EventBridgeルール設定**（CDK追加で数時間）
   - Webhook受信 → EventBridge → WebhookEventFlow の接続

2. **定期バッチ3本**（Lambda + EventBridge Scheduler）
   - subscriptionSyncBatch.ts
   - expiredPlanCheckBatch.ts
   - counterResetBatch.ts

3. **ユーザ向け解約API**
   - cancelSubscription.ts（期限終了時解約パターン）

### Phase 2: 本番運用に向けて

4. **不整合検出・修正ロジック**
5. **通知機構**（最低限メール通知）
6. **監視・ダッシュボード**

### Phase 3: ネイティブアプリ対応

7. **Apple/Google検証実装**
8. **Apple/Google Webhook受信処理**
