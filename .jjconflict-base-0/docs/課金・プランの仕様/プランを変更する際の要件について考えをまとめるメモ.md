# プランを変更する際の要件について考えをまとめるメモ
`プラン体系変更パターンの網羅的調査.md`では、一般的なSaaSでのプラン形態を変更したり、価格を変えたり、既存プランのオプションを増やしたり減らしたり内容を変えたりといったことがどのように行われるのかをまとめたもの

ここからは、システム内部としてプランやサブスクリプションといったものを本質的にどのように扱うべきなのかの考えをメモ書き程度にまとめる

前提として、カタログという概念が必要
カタログは、「その時点で契約として有効なものの一覧」を表している
下記のようなイメージのもの
```
カタログ
- Id
- プラットフォーム: "Web(Stripe)" | "Apple" | "Google"
- バージョンNo: 
- Items: カタログに並ぶアイテムのリスト
- 変更ノート: string;         // 例: "Proプラン追加、Basic廃止"
- etc...
```
これはイミュータブルなものである。
itemsとは、プランと価格の参照を持つものである。
プランというものにはデータとして価格というものを含まない
プラットフォームごとに価格が変わるかもしれないということを踏まえ、プランと価格は完全に分離したものとして扱う
プランや価格というものもイミュータブル。
プランはバージョン管理されるような感じにするが、これは管理ページ上で見やすく表示することができるようにするための意味合いが強い

システム管理者がプランを変更したりする時の作業イメージを記述する
```
システム管理者がカタログ一覧ページを開いているとするじゃないですか
FreeとStandardの二つがありますよと
Standardですが、Stripe版に限り値段を上げることになったとするじゃないですか
新しいバージョンのカタログを作成することになると思います。
まず、Stripe側の新しい価格オブジェクト(Product?)を作成します。
そして、Stripeのカタログの新しいバージョンを作成する作業に入ります。
以前のバージョンの状態が初期状態として新規作成ページが開かれます。
FreeとStandardの二つのアイテム並んでいることが伺えます。
二つの選択肢があります。
1 既存のプラン加入者は継続して価格が維持される
2 既存のプラン加入者はFreeプランへ自動的に移行する
1の場合、すでにあるStandardプランアイテムのメニューを開き、設定の「新規契約を不可にし、非表示にする」を選択します。
こうすることで、ユーザが新規契約可能なプランではなくなりますし、プランの存在は不可視の状態になります
そして、新しい価格オブジェクトと、以前と同じバージョンのプランを参照したStandardプランアイテムを別で作成し、完了です。
画面には、
- Freeプラン
- Standardプラン(新規加入不可)
- Standardプラン
の三つが表示されていることになります。
この三つが現在ユーザが契約しうる形態の全てを表現していることになります。

2の場合ですが
先に新しい価格オブジェクトと、以前と同じバージョンのプランを参照したStandardプランアイテムを別で作成したとします。順序は後でもかまいません。
そして古い方のStandardプランのメニューを開き、「削除する」を選択します。
この時、入力必須の項目として、既存のStandardプラン加入者の移行先を確認する設定項目が開かれます。
移行が可能なのは、下記のようなものになります
- デフォルトで適用されるプラン(Freeプランなど)のアイテム
- 同一の価格オブジェクトを参照しているアイテム
今回新規で追加したStandardプランは同一の価格オブジェクトではないので、選択肢の中には含まれません。Freeプランのみが選択可能です。

1,2のどちらかのパターンで設定をした後、このカタログをいつ適用するのかを設定し、保存をすると完了です。
```
