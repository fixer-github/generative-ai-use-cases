# プラン概念定義書

## 目的

このドキュメントでは、本システムにおける「プラン」という概念の本質、その表現可能性、および技術的な実現方法を明確に定義します。

---

## 1. プランとは何か（概念定義）

### 1.1 プランの定義

**プラン（Plan）** とは、**ユーザが利用可能なサービスの範囲と条件を定義した契約単位**です。

プランは以下の要素で構成されます：

1. **利用可能な権利の集合（What）**
   - どのLLMモデルにアクセスできるか
   - どの機能（Feature）を使えるか
   - それぞれに対する利用制限（無制限 or 回数制限）

2. **期限情報（When）**
   - いつまでそのプランが有効か
   - 自動更新の有無

3. **適用理由（Why）**
   - サブスクリプション契約による適用
   - 管理者による手動適用
   - トライアル期間による適用
   - デフォルトプランとしての自動適用

### 1.2 プランの特性

#### プランはビジネス層の概念である

```
[ビジネス層]
  └─ プラン管理サービス
      ↓ 依存
[認可層]
  └─ 権限管理サービス（OpenFGA + 回数制限管理）
```

- **プラン**はToC（Consumer向け）ビジネスモデルで登場する概念
- ToB（Business向け）では、プランを経由せず直接権限が付与される可能性がある
- 認可システム（OpenFGA）自体は「プラン」を知らない

#### プランは動的である

- プランの内容（含まれる権利）は変更可能
- 例：「Standardプランでモデルの月間利用回数を400回→600回に変更」
- 既存契約者への影響範囲は運用ポリシーによる

#### プランと支払いは別物である

- **サブスクリプション（Subscription）**: 支払いの継続状態
- **プラン（Plan）**: その支払いの結果として得られる権利の集合

## 2. プランの技術的実現

### 2.1 プランの分解構造

プランは以下のように分解され、システムに格納されます：

```
プラン「Standard」
  ├─ プラン定義（メタ情報）
  │   ├─ プランID: "plan-standard"
  │   ├─ プラン名: "Standard"
  │   ├─ 表示順序
  │   └─ 説明文
  │
  ├─ 権利セット（Entitlements）
  │   ├─ 権利A: LLMモデル「Claude 3.5 Sonnet」への無制限アクセス
  │   ├─ 権利B: LLMモデル「Claude 3 Opus」への月間400回アクセス
  │   ├─ 権利C: 機能「chat」へのアクセス
  │   ├─ 権利D: 機能「rag」へのアクセス
  │   └─ 権利E: 機能「image-generation」へのアクセス
  │
  └─ 契約情報（ユーザごと）
      ├─ 契約開始日時
      ├─ 契約終了日時
      ├─ 適用理由（subscription/manual/trial/default）
      └─ サブスクリプションID（該当する場合）
```

### 2.2 権限管理サービスへのマッピング

プランが適用されると、以下の処理が実行されます：

#### ステップ1: Entitlementの作成

```json
// DynamoDB等に保存される権利付与レコード
{
  "grantId": "grant-abc123",
  "userId": "user-001",
  "planId": "plan-standard",
  "createdAt": "2025-01-15T00:00:00Z",
  "expiresAt": "2025-02-15T00:00:00Z",
  "source": "subscription",
  "subscriptionId": "sub-stripe-xyz789"
}
```

#### ステップ2: OpenFGAへのTuple登録

```typescript
// OpenFGAに登録される権限関係
[
  // LLMモデルへのアクセス権（無制限）
  {
    user: "entitlement:grant-abc123",
    relation: "holder",
    object: "entitlement:llm-claude-3.5-sonnet-unlimited"
  },
  {
    user: "llm:claude-3-5-sonnet-20241022-v2:0",
    relation: "via_access",
    object: "entitlement:llm-claude-3.5-sonnet-unlimited"
  },

  // 機能へのアクセス権
  {
    user: "entitlement:grant-abc123",
    relation: "holder",
    object: "entitlement:feature-chat"
  },
  {
    user: "feature:chat",
    relation: "via_enable",
    object: "entitlement:feature-chat"
  }
]
```

#### ステップ3: 回数制限の登録（必要に応じて）

```json
// DynamoDBの回数管理テーブル
{
  "userId": "user-001",
  "resourceId": "llm:claude-3-opus-20240229-v1:0",
  "grantId": "grant-abc123",
  "limitType": "monthly",
  "maxCount": 400,
  "currentCount": 0,
  "resetAt": "2025-02-01T00:00:00Z"
}
```

### 2.3 プラン適用のパターン

#### パターン1: デフォルトプラン

```json
{
  "planId": "plan-free",
  "source": "default",
  "expiresAt": null  // 無期限（他のプランが適用されるまで）
}
```

- 新規ユーザー登録時に自動適用
- サブスクリプション契約がない状態で提供される基本プラン

#### パターン2: サブスクリプションプラン

```json
{
  "planId": "plan-standard",
  "source": "subscription",
  "subscriptionId": "sub-stripe-xyz789",
  "expiresAt": "2025-02-15T00:00:00Z",  // 次回更新日
  "autoRenew": true
}
```

- 課金プラットフォーム（Stripe/Apple/Google）経由で契約
- 定期的な支払いと更新が行われる

#### パターン3: 管理者手動適用

```json
{
  "planId": "plan-enterprise",
  "source": "manual",
  "adminUserId": "admin-005",
  "reason": "特別対応：サポート問い合わせ対応",
  "expiresAt": "2025-12-31T23:59:59Z"
}
```

- 例外的な対応、カスタマーサポート対応等で使用
- 監査ログに記録される

#### パターン4: トライアル／キャンペーン

```json
{
  "planId": "plan-premium-trial",
  "source": "trial",
  "campaignId": "campaign-2025-jan",
  "expiresAt": "2025-01-31T23:59:59Z",
  "autoRenew": false
}
```

- 期間限定のプロモーション
- 期限到着後は自動的にデフォルトプランに戻る

## 3. プランで表現可能なこと

### 3.1 アクセス権の制御

#### モデルレベルでの制御

```yaml
プランA:
  - Claude 3.5 Sonnet: 無制限
  - Claude 3 Opus: 利用不可

プランB:
  - Claude 3.5 Sonnet: 無制限
  - Claude 3 Opus: 月間400回
  - Claude 3.5 Haiku: 無制限
```

#### 機能レベルでの制御

```yaml
プランA:
  機能:
    - chat: 利用可能
    - image-generation: 利用不可
    - rag: 利用不可

プランB:
  機能:
    - chat: 利用可能
    - image-generation: 利用可能
    - rag: 日次10回
```

### 3.2 回数制限の種類

| 制限タイプ | 説明 | リセットタイミング | 例 |
|-----------|------|-------------------|-----|
| `unlimited` | 無制限 | - | Standardプランでの基本モデル |
| `daily` | 日次制限 | 毎日00:00 UTC | Freeプランで1日10回 |
| `monthly` | 月次制限 | 毎月1日00:00 UTC | モデルCへ月間400回 |
| `total` | 累計制限 | リセットなし | トライアルで累計100回 |

### 3.3 階層的なプラン構造

プラン間で階層構造を持たせることも可能：

```
Enterprise (最上位)
  └─ すべてのモデル・機能に無制限アクセス
  └─ 専用サポート（これは権限管理外の特典）

Premium (中位)
  └─ 主要モデルに無制限、一部モデルは月間制限
  └─ 主要機能すべて利用可能

Standard (下位)
  └─ 基本モデルに無制限、高度なモデルは月間制限
  └─ 基本機能のみ

Free (最下位)
  └─ 基本モデルに日次制限
  └─ 基本機能の一部のみ
```

### 3.4 複数プランの同時適用

原則として、ユーザには**1つのプラン**のみが適用されます。
ただし、以下のような特殊ケースでは複数の権利付与が共存する可能性があります：

```
ユーザAの権利状態:
  1. プランStandard（サブスクリプション）
      → 基本的な権利セット
  2. 追加権利（管理者手動付与）
      → 「モデルXへの追加アクセス」
      → 期限: 2週間
```

この場合、権限チェック時は**OR条件**で評価されます（いずれかの権利で許可されればOK）。

## 4. プランで表現できないこと

### 4.1 使用量ベースの従量課金

プランは「定額の権利セット」です。以下のような従量課金は**プランの範囲外**：

```
例: トークン数課金
  - Claude 3.5 Sonnetを1Mトークンまで無料
  - 超過分は$0.015/1Kトークン

→ これは別途「使用量追跡・課金システム」が必要
```

### 4.2 動的な価格設定

```
例: 時間帯別料金
  - 昼間: 通常料金
  - 深夜: 30%割引

→ プランは価格情報を持たない（価格はStripe等で管理）
```

### 4.3 リソースの品質制御

```
例: 応答速度の優先度
  - Enterpriseプラン: 高優先キュー
  - Freeプラン: 通常キュー

→ これはアプリケーション層のロジックで実装
```

### 4.4 複雑な組み合わせ条件

```
例: 条件付きアクセス
  - 「モデルAとモデルBを合計で月間500回まで」
  - 「機能Xを使った場合のみ機能Yも利用可能」

→ 現在の設計では各リソースを独立して管理
→ 複雑な条件はカスタムロジックが必要
```

## 5. 実装時の考慮事項

### 5.1 プラン変更時の挙動

#### ケース1: アップグレード

```
Free → Standard への変更

処理:
  1. 新しいプランのEntitlementを作成
  2. 古いプランのEntitlementを無効化（expiresAtを現在時刻に設定）
  3. 回数カウンターは引き継がない（リセット）
```

#### ケース2: ダウングレード

```
Standard → Free への変更

処理:
  1. 次回更新日まで現在のStandardを維持
  2. 更新日に自動的にFreeプランを適用
  3. 使えなくなる機能へのアクセスは拒否される
```

#### ケース3: プラン内容の変更

```
Standardプランの定義変更:
  「月間400回 → 月間600回」

影響:
  - 新規契約者: 新しい定義で適用
  - 既存契約者:
    Option A) 次回更新時に新定義を適用
    Option B) 即座に新定義を適用
    → 運用ポリシーによる
```

### 5.2 期限切れの処理

```typescript
// 毎時実行されるバッチ処理（EventBridge + Lambda）
async function checkExpiredPlans() {
  const expiredGrants = await db.findExpiredGrants();

  for (const grant of expiredGrants) {
    // OpenFGAからTupleを削除
    await openFGA.deleteTuples(grant.tuples);

    // 回数制限レコードを削除
    await db.deleteQuotaRecords(grant.grantId);

    // デフォルトプランを適用
    await applyDefaultPlan(grant.userId);

    // ユーザーへ通知
    await notify(grant.userId, 'plan_expired');
  }
}
```

### 5.3 回数制限のリセット

```typescript
// 日次リセット（毎日00:00 UTC実行）
async function resetDailyQuotas() {
  await db.updateAll({
    limitType: 'daily',
    currentCount: 0,
    resetAt: addDays(now(), 1)
  });
}

// 月次リセット（毎月1日00:00 UTC実行）
async function resetMonthlyQuotas() {
  await db.updateAll({
    limitType: 'monthly',
    currentCount: 0,
    resetAt: addMonths(now(), 1)
  });
}
```

## 6. プランの具体例

### 例1: Freeプラン（デフォルト）

```yaml
planId: plan-free
name: Free
description: 基本機能を無料で体験
price: $0/month

entitlements:
  llm:
    - model: claude-3-5-haiku-20241022-v1:0
      limit: daily
      maxCount: 10

  features:
    - feature: chat
      limit: unlimited
    - feature: summarize
      limit: daily
      maxCount: 5

application:
  source: default
  autoApply: true  # 新規ユーザーに自動適用
```

### 例2: Standardプラン

```yaml
planId: plan-standard
name: Standard
description: 日常的な業務利用に最適
price: $20/month

entitlements:
  llm:
    - model: claude-3-5-sonnet-20241022-v2:0
      limit: unlimited
    - model: claude-3-5-haiku-20241022-v1:0
      limit: unlimited
    - model: claude-3-opus-20240229-v1:0
      limit: monthly
      maxCount: 400

  features:
    - feature: chat
      limit: unlimited
    - feature: rag
      limit: unlimited
    - feature: summarize
      limit: unlimited
    - feature: translate
      limit: unlimited
    - feature: image-generation
      limit: monthly
      maxCount: 100

application:
  source: subscription
  platforms:
    - stripe
    - apple
    - google
```

### 例3: Enterpriseプラン

```yaml
planId: plan-enterprise
name: Enterprise
description: すべての機能を無制限に利用
price: $200/month

entitlements:
  llm:
    - model: "*"  # すべてのモデル
      limit: unlimited

  features:
    - feature: "*"  # すべての機能
      limit: unlimited

application:
  source: subscription
  platforms:
    - stripe
  customization: true  # カスタマイズ可能
```

### 例4: トライアルプラン

```yaml
planId: plan-standard-trial
name: Standard (Trial)
description: Standardプランの14日間無料トライアル
price: $0 (trial)
basedOn: plan-standard  # Standardプランと同じ権利

  # plan-standardと同じ内容を継承

  source: trial
  duration: 14 days
  autoExpire: true  # 期限後はplan-freeに戻る
```

## 7. まとめ

### プランの本質

- プランは「ユーザが利用できる権利の集合」を表現するビジネス概念
- 技術的には「Entitlementのセット + 期限情報 + 適用理由」として実装される
- 認可システム（OpenFGA）からは独立しており、上位レイヤーで管理される

### プランの柔軟性

- 新しいプランの追加・変更は容易
- モデル、機能、回数制限の組み合わせで多様なプランを表現可能
- 適用パターン（サブスク/手動/トライアル/デフォルト）を使い分け可能

### プランの制約

- 従量課金や動的価格設定には対応しない
- リソースをまたいだ複雑な制限は困難
- 品質制御（優先度、SLA等）はプランの範囲外

---

## 付録: 用語集

| 用語 | 定義 |
|-----|------|
| **Plan（プラン）** | ユーザが契約するサービスの範囲と条件を定義したもの |
| **Entitlement（権利）** | 特定のリソース（モデル/機能）へのアクセス権。プランを構成する最小単位 |
| **Grant（付与）** | ユーザに対してEntitlementを適用する行為、またはその記録 |
| **Subscription（サブスクリプション）** | 課金プラットフォーム上での定期支払い契約 |
| **Quota（クォータ）** | 回数制限や使用量制限 |
| **Source（適用理由）** | プランがどのような理由で適用されたか（subscription/manual/trial/default） |
| **Authorization Model** | OpenFGAにおける権限の定義（type, relation） |
| **Tuple** | OpenFGAにおける具体的な権限関係のレコード |
